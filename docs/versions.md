# 지표·시그널 버전과 성과 계산 변경

2026-11-15 · 비교 기준 커밋 `1acbf7cc5f33f93bc2e21589298a7c944dbca788`

이 문서의 v1.0.0은 위 커밋에 새로 부여한 비교 기준이다. 기존 Git 배포 태그를 뜻하지 않는다. 현재 버전은 `config/analysis-versions.json`에서 항목별로 관리한다. 지표 수식 34개는 v1.0.0을 유지하고, 상태 신호 4개·전략 63개·캔들 패턴 26개·차트 패턴 15개·공통 엔진 7개는 v2.0.0이다.

## 무엇이 좋아지는가

나중에 얻은 피벗이나 지지·저항 정보를 과거 진입에 쓰는 오류를 줄인다. 각 봉까지의 데이터만으로 분석을 다시 실행하고 처음 확인된 이벤트를 보존한다. 신호의 과거 발생 위치(`originBarIndex`)와 실제 관측 시점(`confirmedBarIndex`, `confirmedDate`)을 구분한다. 이후 데이터가 늘어도 기존 이벤트의 날짜·손절·목표를 바꾸지 않는다. 이 보장은 같은 시작일·설정·원본 가격을 가진 데이터에 적용한다. 수정주가나 분석 시작일을 바꾸면 별도 분석이다.

예를 들어 P봉의 저점에 오른쪽 두 봉 확인이 필요한 RSI 다이버전스는 최소 P+2봉이 끝나야 확인되고, 진입은 P+3봉 시가부터 가능하다. 차트 도형의 꼭짓점은 P봉에 남을 수 있지만 거래는 그 시점으로 소급하지 않는다. 캔들 패턴의 확정은 현재 코드의 패턴 조건 충족을 뜻하며, 설명 문서의 모든 추가 확인 조건을 새로 강제한 것은 아니다.

수정 후 성공률이 낮아지거나 신호가 늦어질 수 있다. 이번 수정은 비교 기준의 오류를 고친 것이며 수익성 개선이나 예측력 향상을 검증한 결과는 아니다.

신호 옆 성공률은 각 신호를 독립적으로 관찰한다. 같은 기간에 겹친 여러 신호도 포함되며, 완료 3건 이상일 때만 비율을 표시한다. 따라서 연속 포트폴리오 수익률과 같지 않다. 플레이북 백테스트는 동시에 한 포지션만 보유하고 양방향 진입 충돌은 건너뛴다. 같은 봉·같은 방향의 신호가 여러 개면 ID 사전순 첫 신호를 선택한다. 신호 통계에는 반대 신호 청산이 없으므로 동일 전략이라도 플레이북 승률과 다를 수 있다.

총수익은 완료 거래만 복리로 계산한다. 낙폭은 미종결 포지션의 종가 평가손익도 반영하며 장중 최악의 평가손실을 뜻하지 않는다. 대차료는 진입일부터 경과한 달력 일수/365로 단순 계산한다. 세금·공매도 가능 여부·증거금/강제청산·호가 잔량은 모델링하지 않는다.

## 봉 확정과 데이터 추적

현재 파일에는 거래소별 장 마감·휴장 캘린더가 없다. 따라서 `fetchedAt`을 관측 기준으로 삼아 일봉은 다음 UTC 자정, 주봉은 다음 월요일 UTC 자정, 월봉은 다음 달 1일 UTC 자정 이후에만 계산에 사용한다. `isComplete: false`인 봉은 항상 제외한다. 이 보수적 기준은 실제 장이 끝난 당일이나 금요일에도 신호를 더 늦게 표시할 수 있다. 거래소별 마감 시각을 정확히 처리하려면 수집 데이터에 해당 정보를 추가하는 별도 변경이 필요하다.

JSON 내보내기에는 전체 항목 버전·지표 설정·점수 설정·추세선 알고리즘·시간 단위·관측 시각·분석 시작/종료일·OHLCV 지문을 포함한다. 지문은 FNV-1a 32비트로, 보안용 해시가 아닌 데이터 식별 보조값이다. 각 거래에는 전략 버전과 체결 엔진 버전을 남긴다. 백테스트 설정 변경 시 이전 결과는 내보내기에서도 비운다.

현재 분석은 매 과거 시점을 재계산하므로 전체 데이터 한 번 계산보다 느리다. 브라우저에서는 Web Worker로 실행하고 종목·설정 변경 시 이전 작업을 취소한다.

## 검증과 범위

회귀 테스트 20개와 `npm run build`가 통과했다. 브라우저에서는 NVDA 일봉 분석, classic 전략 실행, 비용 변경 시 결과 초기화, 비용 반영, 잘못된 수식의 오류 표시를 확인했다. 로컬 `.env.example` 설정을 사용했고 외부 폰트 지연을 피하려고 검증용 `dist/index.html`에서 CDN 폰트 링크만 일시 제외했다. 소스 HTML은 원상 복구했다. 빌드의 큰 청크 경고는 남아 있다.

`npm run test:evaluation`은 다음 봉 진입, 손절/목표 동시 접촉, 롱/숏 갭, 무효 진입, 미종결, 비용, 반대 신호 청산, 충돌, 본전, 보유 중 낙폭, OR, classic 연결, 봉 확정, 이벤트 고정, 버전 누락 및 실제 NVDA 데이터의 과거 이벤트 불변성을 확인한다. `npm run build`로 TypeScript와 배포 번들을 검사한다.

지표 임계값의 최적화, 패턴 경계선 자체의 정확도, 엘리엇 파동의 예측력, RR 참고 도형의 자동매매 연결, 표본 외 수익성 검증은 이번 변경에 포함되지 않는다. 저수준 `detect*` 함수는 후보 도형 탐지용이며, 확정 신호·성과를 이용하는 호출자는 `evaluateQuote` 또는 `evaluateAsync`를 사용해야 한다.
